# Тестовое задание: мини-карточка лида для CRM

Решение: один файл `index.html`. Открывается двойным кликом, без установки
и без сборки. Внешних библиотек нет.

---

## 1. Работающая страница

Откройте `index.html` в браузере. Вверху форма добавления лида, ниже список
сохранённых.

## 2. Добавление нового лида

Заполните имя и телефон, при желании измените источник, ответственного,
этап и переключатель «Запрошено ТЗ», нажмите «Сохранить». Лид появляется
карточкой ниже формы, новые сверху. Форма очищается и фокус возвращается
на поле имени, чтобы можно было вносить лиды подряд.

## 3. Проверка обязательных полей

- Пустое имя: «Укажите имя клиента»
- Пустой телефон: «Укажите телефон»
- Телефон короче 10 цифр: «В номере должно быть минимум 10 цифр»

Сообщение появляется под самим полем, поле подсвечивается. Ошибка исчезает,
как только начинаешь исправлять поле, а не висит до следующего нажатия
кнопки.

Имя из одних пробелов не считается заполненным.

## 4. Сохранение данных после обновления страницы

Лиды хранятся в `localStorage` под ключом `crm.leads.v1`. При загрузке
страницы список читается один раз и отрисовывается. Нажмите F5 — карточки
останутся.

Смена этапа и удаление тоже сразу пишутся в хранилище.

## 5. Где что находится в коде

Файл размечен комментариями-разделителями, искать удобно поиском по слову.

| Что | Где | Ориентир |
|---|---|---|
| Интерфейс, оформление | `<style>` в начале файла | блок `1. ИНТЕРФЕЙС (оформление)` |
| Интерфейс, разметка формы | `<form id="leadForm">` | блок `1. ИНТЕРФЕЙС (разметка формы)` |
| Интерфейс, отрисовка списка | функция `render()` | блок `1. ИНТЕРФЕЙС (отрисовка списка лидов)` |
| Логика кнопки | обработчик `form.addEventListener("submit", ...)` | блок `2. ЛОГИКА КНОПКИ` |
| Проверка полей | функция `validate(name, phone)` | там же |
| Сохранение данных | функции `loadLeads()` и `saveLeads()` | блок `3. СОХРАНЕНИЕ ДАННЫХ` |
| Дополнительное задание | функция `sendToCrm(lead)` | блок `ДОПОЛНИТЕЛЬНОЕ ЗАДАНИЕ` |

## Дополнительное задание

Сделаны оба варианта, потому что каждый занял немного.

**Смена этапа.** В каждой карточке есть выпадающий список этапов. Выбор
сразу меняет этап и пишется в хранилище.

**Отправка через API.** Функция `sendToCrm(lead)` отправляет `POST` с телом
в JSON:

```javascript
fetch("https://httpbin.org/post", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    name: lead.name,
    phone: lead.phone,
    source: lead.source,
    owner: lead.owner,
    stage: lead.stage,
    tz_requested: lead.tz,
    created_at: lead.createdAt,
  }),
});
```

**Куда уходит запрос.** В боевой системе это был бы эндпоинт приёма лидов
вашей CRM, например `POST https://crm.example.com/api/v1/leads`, с токеном
в заголовке `Authorization` (место под него оставлено комментарием).

Здесь вместо него стоит `httpbin.org/post` — публичный сервис, который
возвращает полученное тело обратно. Так видно настоящий сетевой запрос во
вкладке Network, не имея доступа к боевой CRM.

Важная деталь: локальное сохранение происходит **до** отправки. Поэтому
обрыв сети не теряет лид — он остаётся в списке, а пользователь видит
«Лид сохранён локально, но отправить в CRM не удалось».

Задание разрешает использовать нейросети, поэтому отвечаю прямо.

Первую версию файла целиком сгенерировал Claude по описанию задачи:
разметку формы, оформление, обработчик кнопки, функции чтения и записи

## 7. Что проверил и исправил самостоятельно

**Нашёл и починил коллизию идентификаторов.** Это главная правка.

Изначально id лида брался как `Date.now()`. Два сохранения внутри одной
миллисекунды получают одинаковый id, и дальше ломается всё, что ищет лид
по нему: удаление вырезает **оба** лида (`filter` убирает всех с этим id),
а смена этапа применяется не к той карточке (`find` возвращает первую).

Руками так быстро не нажать, поэтому на глаз баг не виден. Нашёл его
проверкой: сохранил подряд в одном тике несколько лидов и сравнил число
записей с числом уникальных id. Получилось 8 записей и 7 идентификаторов.
Затем нажал «Удалить» на одной карточке и увидел, что исчезли две.

Заменил на счётчик, который стартует от максимального сохранённого id и
не может выдать повтор:

```javascript
let lastId = leads.reduce((max, lead) => Math.max(max, Number(lead.id) || 0), 0);

function nextId() {
  const now = Date.now();
  lastId = now > lastId ? now : lastId + 1;
  return lastId;
}
```

После правки: 20 сохранений подряд дают 20 уникальных id, удаление убирает
ровно одну карточку, смена этапа попадает в нужную.

**Нашёл и убрал бессмыслицу в коде.** В обработчике смены этапа стояло
`saveLeads(lead && leads)`. Работает случайно: `lead` истинный, поэтому
выражение возвращает `leads`. Но читается как ошибка и сбивает с толку.
Заменил на `saveLeads(leads)`.

**Прогнал сценарии, на которых такие формы обычно ломаются:**

- Пустая форма: обе ошибки показываются, карточка не создаётся.
- Имя из одних пробелов: отклоняется. Без `.trim()` такая строка проходит
  проверку `if (!name)`, и в CRM попадает лид без имени.
- Телефон из пяти цифр: отклоняется по количеству цифр, а не по длине
  строки, иначе `+7 (999)` без номера прошло бы.
- Ошибка после исправления: снимается по событию `input`, а не висит до
  следующего нажатия кнопки.
- Перезагрузка страницы: список восстанавливается. Это отдельно проверял,
  потому что типичная ошибка — записывать в хранилище, но не читать из
  него при старте. Тогда всё выглядит рабочим до первого F5.
- Битые данные в хранилище: подложил в `localStorage` строку `{ это не json`,
  объект вместо массива и массив с мусором внутри — `[1, "строка", null, {foo:1}]`.
  Во всех случаях страница открывается и остаётся работоспособной.

  Последний случай оказался самым коварным и попался не сразу. Проверять
  только контейнер через `Array.isArray` мало: `[null]` — валидный JSON и
  валидный массив, но обращение к полям такого элемента бросает
  `TypeError`. Причём это исключение возникало на верхнем уровне скрипта,
  до навешивания обработчиков, поэтому обрывалось **всё, что ниже**:
  форма оставалась на экране, выглядела нормально, но кнопка «Сохранить»
  переставала работать вообще. Внешне страница целая, по факту мёртвая.

  Отдельно неприятно, что этот дефект внёс мой же фикс идентификаторов:
  до него первое обращение к полям лида происходило внутри `render()`,
  то есть уже после навешивания обработчиков, и форма продолжала работать.
  Теперь `loadLeads()` отсеивает элементы, которые не являются объектами
  с числовым `id`.
- Обрыв сети при отправке: подменил `fetch` на отклоняющий промис. Лид
  сохраняется локально, показывается предупреждение, данные не теряются.

**Добавил экранирование ввода и проверил его.** Всё, что вводит
пользователь, проходит через `esc()` перед вставкой в разметку. Проверял
не теоретически: ввёл в поле имени `<img src=x onerror="...">` и убедился,
что в карточке это осталось текстом, тег в DOM не появился, скрипт не
выполнился. Отдельно проверил имя с кавычками и апострофами — вёрстка
карточки и атрибуты кнопок не ломаются.

**Довёл до конца обработку отказа записи.** `saveLeads()` раньше просто
глушил исключение в `console.warn`, и вызывающий код об этом не узнавал:
интерфейс показывал успех, лид появлялся в списке (он же в памяти), а после
перезагрузки исчезал. Теперь функция возвращает признак неудачи, и человек
видит предупреждение, что лид не сохранён. Проверял подменой
`Storage.prototype.setItem` на бросающий `QuotaExceededError`.

**Убрал гонку ответов при отправке в CRM.** Статус писался в общий блок из
колбэка `fetch` без привязки к конкретной отправке, поэтому запоздавший
ответ от предыдущего лида перетирал статус текущего — вплоть до «отправлено»
там, где отправка провалилась. Добавил номер отправки: колбэк пишет статус,
только если он всё ещё актуальный. Проверял, искусственно задержав первый
ответ дольше второго.

**Добавил синхронизацию между вкладками.** Страница работает со снимком
массива в памяти, а запись идёт целиком. Две открытые вкладки затирали бы
лиды друг друга. Обработчик события `storage` перечитывает данные, когда
их изменила соседняя вкладка.

**Доступность.** `role="alert"` блокам ошибок, `role="status"` и
`aria-live="polite"` блоку результата отправки. У селекта этапа и кнопки
удаления в каждой карточке проставляется `aria-label` с именем лида: без
этого скринридер объявляет десять безымянных комбобоксов и десять
одинаковых кнопок «Удалить».

**Сохранил фокус при работе с карточками.** Смена этапа больше не
перерисовывает весь список: этап нигде, кроме самого селекта, не
отображается, а полная перерисовка удаляла бы селект во время обработки
его же события и роняла фокус на `body`. После удаления фокус переходит
на кнопку, занявшую освободившееся место, а если список опустел — в поле
имени. Иначе клавиатурному пользователю после каждого действия пришлось бы
таббиться от начала страницы.

**Оформил код разделами** под пункт 5 задания, чтобы интерфейс, логика
кнопки и сохранение искались за секунду, а не читались целиком.
