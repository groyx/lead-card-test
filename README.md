# Тестовое задание: мини-карточка лида для CRM

Решение: один файл `index.html`. Открывается двойным кликом, без установки
и без сборки. Внешних библиотек нет.

---

## 1. Работающая страница

Откройте `index.html` в браузере. Вверху форма добавления лида, ниже список
сохранённых.

## 2. Добавление нового лида

Заполните имя и телефон, при желании измените источник, ответственного,
этап и переключатель «Запрошено ТЗ», нажмите «Сохранить». Лид появляется
карточкой ниже формы, новые сверху. Форма очищается и фокус возвращается
на поле имени, чтобы можно было вносить лиды подряд.

## 3. Проверка обязательных полей

- Пустое имя: «Укажите имя клиента»
- Пустой телефон: «Укажите телефон»
- Телефон короче 10 цифр: «В номере должно быть минимум 10 цифр»

Сообщение появляется под самим полем, поле подсвечивается. Ошибка исчезает,
как только начинаешь исправлять поле, а не висит до следующего нажатия
кнопки.

Имя из одних пробелов не считается заполненным.

## 4. Сохранение данных после обновления страницы

Лиды хранятся в `localStorage` под ключом `crm.leads.v1`. При загрузке
страницы список читается один раз и отрисовывается. Нажмите F5 — карточки
останутся.

Смена этапа и удаление тоже сразу пишутся в хранилище.

## 5. Где что находится в коде

Файл размечен комментариями-разделителями, искать удобно поиском по слову.

| Что | Где | Ориентир |
|---|---|---|
| Интерфейс, оформление | `<style>` в начале файла | блок `1. ИНТЕРФЕЙС (оформление)` |
| Интерфейс, разметка формы | `<form id="leadForm">` | блок `1. ИНТЕРФЕЙС (разметка формы)` |
| Интерфейс, отрисовка списка | функция `render()` | блок `1. ИНТЕРФЕЙС (отрисовка списка лидов)` |
| Логика кнопки | обработчик `form.addEventListener("submit", ...)` | блок `2. ЛОГИКА КНОПКИ` |
| Проверка полей | функция `validate(name, phone)` | там же |
| Сохранение данных | функции `loadLeads()` и `saveLeads()` | блок `3. СОХРАНЕНИЕ ДАННЫХ` |
| Дополнительное задание | функция `sendToCrm(lead)` | блок `ДОПОЛНИТЕЛЬНОЕ ЗАДАНИЕ` |

## Дополнительное задание

Сделаны оба варианта, потому что каждый занял немного.

**Смена этапа.** В каждой карточке есть выпадающий список этапов. Выбор
сразу меняет этап и пишется в хранилище.

**Отправка через API.** Функция `sendToCrm(lead)` отправляет `POST` с телом
в JSON:

```javascript
fetch("https://httpbin.org/post", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    name: lead.name,
    phone: lead.phone,
    source: lead.source,
    owner: lead.owner,
    stage: lead.stage,
    tz_requested: lead.tz,
    created_at: lead.createdAt,
  }),
});
```

**Куда уходит запрос.** В боевой системе это был бы эндпоинт приёма лидов
вашей CRM, например `POST https://crm.example.com/api/v1/leads`, с токеном
в заголовке `Authorization` (место под него оставлено комментарием).

Здесь вместо него стоит `httpbin.org/post` — публичный сервис, который
возвращает полученное тело обратно. Так видно настоящий сетевой запрос во
вкладке Network, не имея доступа к боевой CRM.

Важная деталь: локальное сохранение происходит **до** отправки. Поэтому
обрыв сети не теряет лид — он остаётся в списке, а пользователь видит
«Лид сохранён локально, но отправить в CRM не удалось».

## 7. Что проверил и исправил самостоятельно

**Нашёл и убрал бессмыслицу в коде.** В обработчике смены этапа стояло
`saveLeads(lead && leads)`. Работает случайно: `lead` истинный, поэтому
выражение возвращает `leads`. Но читается как ошибка и сбивает с толку.
Заменил на `saveLeads(leads)`.

**Прогнал сценарии, на которых такие формы обычно ломаются:**

- Пустая форма: обе ошибки показываются, карточка не создаётся.
- Имя из одних пробелов: отклоняется. Без `.trim()` такая строка проходит
  проверку `if (!name)`, и в CRM попадает лид без имени.
- Телефон из пяти цифр: отклоняется по количеству цифр, а не по длине
  строки, иначе `+7 (999)` без номера прошло бы.
- Ошибка после исправления: снимается по событию `input`, а не висит до
  следующего нажатия кнопки.
- Перезагрузка страницы: список восстанавливается. Это отдельно проверял,
  потому что типичная ошибка — записывать в хранилище, но не читать из
  него при старте. Тогда всё выглядит рабочим до первого F5.
- Битые данные в хранилище: подложил в `localStorage` строку `{ это не json`
  и объект вместо массива. В обоих случаях страница открывается с пустым
  списком, а не падает с белым экраном.
- Обрыв сети при отправке: подменил `fetch` на отклоняющий промис. Лид
  сохраняется локально, показывается предупреждение, данные не теряются.

**Добавил экранирование ввода.** Всё, что вводит пользователь, проходит
через `esc()` перед вставкой в разметку. Имя с угловой скобкой не должно
ломать страницу.

**Оформил код разделами** под пункт 5 задания, чтобы интерфейс, логика
кнопки и сохранение искались за секунду, а не читались целиком.
